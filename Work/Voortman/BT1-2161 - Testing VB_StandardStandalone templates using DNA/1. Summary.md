The goal is to run the VB_StandardStandalone templates (configurable configuration) through the DNA Wizard and test them thoroughly once the CTO team is ready. Experience from LES/B2B has shown that a number of issues typically surface at this stage. By identifying and resolving them early, we avoid them appearing in the Projects department (William Brand), where fixes would have to be made directly under pressure.

**The biggest risk right now** is the sensor standardisation PR blocker. The merge is being held up organisation-wide, so Type 3 testing is only possible with the `TryFindByTag` workaround. TC-14 is specifically designed as a follow-up test case for after Gert Jan reverts that change post-merge — worth tracking that explicitly so it doesn't get lost.

**Two issues are already active** (logged by Marcel de Vries on 22 June, just 2 days ago): the bundle plate check error on configurations without a bundle plate, and the VASIM toggling problem on material detection driven rollers. Both have workarounds but need proper fixes in the template before this ticket can close.

**The test plan is structured in 4 phases** — Smoke (2 TCs to catch basic load/compile issues), Functional (7 TCs targeting each specific defect), Integration (3 TCs for full VASIM end-to-end runs), and Regression (2 TCs — one post-fix, one post-PR-merge). Estimated effort is 3–4 days assuming the CTO team work and DNA environment are ready.
