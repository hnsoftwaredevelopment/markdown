## Context

The goal is to run the VB_StandardStandalone templates (configurable configuration) through the DNA Wizard and test them thoroughly once the CTO team is ready. Experience from LES/B2B has shown that a number of issues typically surface at this stage. By identifying and resolving them early, we avoid them appearing in the Projects department (William Brand), where fixes would have to be made directly under pressure.

Testing is already underway. Three comment threads on the ticket log concrete defects discovered via a real customer project (`20260017 Tiggelovend-Kok B.V. VB750`) and recent DNA Wizard runs by Marcel de Vries on 22 June 2026.

## Active blocker

> [!warning] Sensor standardisation PR merge blocked

> The PRs for sensor standardisation cannot yet be released because the broader organisational change process is not complete. Because merging to `main` directly triggers a release, the PRs are on hold.

>

> **Interim workaround:** Change `FindByTag` to `TryFindByTag` on line 41 of `ProbeTruckFeatureBase` so Type 3 can be pushed through the DNA Wizard.

>

> **Owner of revert:** Gert Jan — once the PRs may be merged, the line must be reverted from `TryFindByTag` back to `FindByTag`. CTO takes responsibility for this revert.

>

> **Consequence:** The MD41 sensor is not yet available in Type 3 from the templates. Projects can add it manually until sensor standardisation completes.
